## 1. 共有導線(最優先)

### なぜやるか

[01_要件定義.md](01_要件定義.md) のコアループは「褒められる → **スクショ → 共有 → 拡散**」だが、
現状は `settled` に「画面をスクショして保存できます」という**案内文があるだけ**で、
アプリからは何も起きない。**MVPの目的そのものである拡散導線が実質存在しない。**

画像生成(html2canvas等)は重いので Phase 1 のままにし、
**Web Share API でネイティブの共有シートを開く**ところまでを Phase 0 でやる。

### 仕様

`settled` の `ResultActions` に「**共有する**」ボタンを追加する(主ボタン)。

```ts
await navigator.share({
  title: "ほめられ",
  text: `「${deed}」で ${yells.toLocaleString()} エールもらいました`,
  url: "https://homarare-app.vercel.app",
});
```

| 項目 | 決定 |
|---|---|
| ボタンの並び | 上から「共有する」(主) → 「もう一度」(副)。案内文は残す |
| 共有する内容 | 投稿文とエール数を含む1行 + アプリのURL |
| 投稿文の長さ | **24文字で切って `…` を付ける。**280文字の全文を載せると共有シートが読めなくなる |
| URL | **本番URL固定**。投稿ごとの共有URLはサーバー保存がないため作れない(Phase 1) |

### 必ず守ること

| 状況 | 挙動 |
|---|---|
| `navigator.share` が無い(PCのFirefox等) | **クリップボードにテキストをコピー**し、「コピーしました」を2秒表示する |
| `navigator.clipboard` も無い | ボタン自体を表示しない。既存の案内文だけにする |
| ユーザーが共有シートを閉じた(`AbortError`) | **握りつぶす。**エラー表示をしない。キャンセルは失敗ではない |
| その他の例外 | 握りつぶす。共有できなくても体験は完結している |

> **`navigator.share` はセキュアコンテキスト(https / localhost)でしか存在しない。**
> `crypto.randomUUID` と同じ罠。スマホ実機を `http://192.168.x.x:3000` で開くと
> 常にフォールバック側に落ちる。**それは正常動作**なので、実機で確認するときは
> 本番URL(https)で見ること。
> また **ユーザー操作(クリック)から直接呼ばないと拒否される。**
> `await` を挟んだ後に呼ぶと失敗する実装があるため、`onClick` 直下で呼ぶ。

## 2. 初回説明(→ 待機画面に統合済み)

### なぜやるか

初回訪問時、画面には「今日やったことを書いてみよう」という入力欄しか出ない。
**何のアプリなのか、書いたら何が起きるのかが分からない**まま離脱する。

> **2026-08-20 改訂: この機能は廃止し、待機画面(タイトル)に統合した。**
> → [03_デザイントークン.md](03_デザイントークン.md) 4-4章
> 同じ説明を入力画面と待機画面の2箇所で言う必要がないため。以下は経緯として残す。

### 旧仕様

**履歴が0件のときだけ**、入力画面に1行を出す。

> やったことを書くだけで、Hのみんなが一斉に褒めてくれます。

| 項目 | 決定 |
|---|---|
| 出す場所 | 入力欄の下。`text-meta` / `text-secondary` |
| 出す条件 | `loadHistory().length === 0` のときのみ。1回でも投稿したら出さない |
| 閉じるボタン | **付けない。**投稿すれば自然に消える |

> **判定は必ずマウント後(`useEffect`)に行う。**
> localStorage をレンダー中に読むとサーバーとクライアントで出力が食い違い、
> ハイドレーション不一致になる。**初期値は「出さない」**にして、
> マウント後に0件と分かった時点で出す(出る側を初期値にすると一瞬ちらつく)。

## 3. 復帰(リロード対策)

### なぜやるか

演出中や `settled` でリロードすると**入力画面に戻る**。
スクショを撮ろうとして誤操作した場合に、見ていた結果が消える。

### 仕様

直近の投稿を復元し、**`settled` の完成形を静止表示**した状態で起動する。

| 項目 | 決定 |
|---|---|
| 保存タイミングの変更 | 履歴への保存を **`settled` 到達時 → `posting` 開始時** に移す |
| 復帰の目印 | `homarare:last:v1` に `{ entryId, savedAt }` を書く |
| 復帰する条件 | `savedAt` から **30分以内**のときだけ |
| 復帰後の見た目 | 演出を再生せず、完成形を静止表示(履歴の詳細画面と同じ扱い) |
| 目印を消すタイミング | 「もう一度」を押したとき / 30分を超えていたとき |
| 再生(履歴からのリプレイ) | **目印を書かない。**リプレイは新しい投稿ではない |

> **なぜ保存タイミングを `posting` に移すのか**
> `settled` 保存のままだと、**演出中(12秒間)にリロードした場合に復元元が存在しない**。
> 投稿した時点で「投稿は成立している」ので、演出の完走を待つ理由がない。
>
> 副作用として、**投稿直後に離脱しても履歴に残る**ようになる。これは望ましい挙動。
> 二重保存の防止(`hasSavedHistoryRef`)と再生時のスキップは**そのまま維持すること。**

> **30分の根拠**
> 「誤操作で消えた」を救うのが目的であり、翌日開いたときに前回の結果が出るのは
> **新しく書く気を削ぐ**。入力画面で迎えるのが正しい。
