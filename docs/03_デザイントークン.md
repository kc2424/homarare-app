# デザイントークン v1.0

- **アプリ名**: ほめられ
- **アプリ内の疑似SNS名**: **H**(一文字ロゴ)
- **ベーステーマ**: ライト(白背景)
- **アクセント**: ブルー `#1D9BF0`

---

## 0. 方針

X のライトテーマのビジュアル言語を **そのまま踏襲する**。
配色・余白・フォントサイズ・角丸・アイコンサイズはすべて本家の数値を採用し、
独自化するのは **ロゴ・サービス名・アクション名** のみとする。

「見た瞬間にあのUIだと分かる」ことが体験の前提条件であり、
ここでオリジナリティを出すと疑似SNS演出そのものが成立しなくなるため。

### 唯一の意図的な逸脱

本家のカウント表記は `1.5万` のように丸められるが、本アプリでは
**エール数だけ常に3桁区切りのフル表示にし、`like` 色で出す**(6章参照)。
カウントアップ演出が体験の主役であり、丸め表記では数字が動かないため。
**サイズ・配置・情報の並びを含め、それ以外はすべて本家準拠とする。**

| `text-secondary` | `#536471` | ハンドル名・時刻・メトリクスラベル |
| `text-on-accent` | `#FFFFFF` | ブルーボタン上の文字 |

### 1-2. アクセント・アクションカラー

| トークン名 | 値 | 用途 |
|---|---|---|
| `accent` | `#1D9BF0` | 主要ボタン・リンク・認証バッジ |
| `accent-hover` | `#1A8CD8` | ボタンホバー |
| `accent-disabled` | `#8ECDF8` | 非活性のブルーボタン。**`opacity` で薄くしない**（文字まで読みにくくなる） |
| `warning` | `#FFD400` | 文字数カウンタの警告（残り20文字以下）。**ここ以外で使わない** |

```css

  --bg-primary: #FFFFFF;

  --border-strong: #CFD9DE;
  --text-primary: #0F1419;
  --text-secondary: #536471;

  --accent: #1D9BF0;
  --accent-hover: #1A8CD8;
```

> Phase 1以降でダーク対応する場合は、この変数群を上書きする形で追加する。

## 2. タイポグラフィ

### 2-1. フォントファミリー

X の本文フォント Chirp は **専用フォントで利用不可**。
本家も日本語部分はシステムフォントにフォールバックしているため、
以下のスタックで実質同じ見た目になる。

```css
--font-sans:
  -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto,
  "Helvetica Neue", "Hiragino Sans", "Hiragino Kaku Gothic ProN",
  "Noto Sans JP", Meiryo, sans-serif;
```

- **Webフォントは読み込まない。** システムフォントを使うことで表示が速く、かつ端末ごとにネイティブな見た目になる
- Google Fonts の Noto Sans JP を読み込む案もあるが、初期表示のちらつきとファイルサイズを避けるため採用しない

### 2-2. タイプスケール

| 用途 | size / line-height | weight | color |
|---|---|---|---|
| ポスト本文(投稿カード) | 17px / 24px | 400 | `text-primary` |
| リプライ本文 | 15px / 20px | 400 | `text-primary` |
| 表示名 | 15px / 20px | **700** | `text-primary` |
| ハンドル名・時刻 | 15px / 20px | 400 | `text-secondary` |
| メトリクスの数値(通常) | 13px / 16px | 400 | `text-secondary` |
| メトリクスのラベル | 13px / 16px | 400 | `text-secondary` |
| ボタンラベル | 15px / 20px | 700 | `text-on-accent` |
| 入力欄プレースホルダ | 20px / 24px | 400 | `text-secondary` |

- 入力欄だけ 20px と大きいのは本家準拠。「これから書く」ことを促す効果がある
- 数字を表示する要素にはすべて `font-variant-numeric: tabular-nums` を指定する

## 4-2. 本家準拠の細部(2026-08-20 実物スクショで確認)

実物と並べたときに「似ていない」と感じる原因は、配色ではなく**情報の密度と並び方**にある。
以下は実物の構造をそのまま踏襲する。

### 表示名とハンドルの並び

| 場所 | 並び |
|---|---|
| **投稿カード** | 表示名とハンドルを**縦2段**にする(`表示名` / 改行 / `@handle`) |
| **リプライカード** | 表示名・ハンドル・時刻を**横1行**に並べる(`表示名 @handle · 今`) |

投稿カードだけ2段なのが本家の仕様。ここを1行にすると情報が詰まって見え、主役感が出ない。

### アクション行には数値を併記する

**数値の置き場はアクション行だけ。** 独立したメトリクス行は置かない(6章)。

| 場所 | アイコンと数値 |
|---|---|
| 投稿カード | 💬 リプライ / 🔁 ひろめる / ♡ エール / 🔖 保存 / ⬆ 共有 の**5個**。共有以外に数値を出す |
| リプライカード | 💬 リプライ / 🔁 ひろめる / ♡ エール / 📊 表示回数 / ⬆ 共有 の**5個**。前4つに数値を出す |

> **リプライ行に保存(🔖)を置かない理由**
> リプライの本文カラムはアバター40px + 余白の分だけ狭く、375px端末で **290px** しかない。
> 6要素だと必要幅が296pxになり、**表示回数が「12.5」と「万」に折り返す**。
> 360px級の端末では行ごとはみ出して横スクロールが出る。
> 保存は数値を持たない装飾要素なので、削っても情報量は落ちない。
> あわせて**リプライ行のアイコン枠だけ28px**にする(投稿カード側は34pxのまま)。

- **0 のときは数字を出さずアイコンのみ**にする。本家と同じ挙動
- 数値は `text-meta`(13px)・`text-secondary`・`tabular-nums`
- **エール数だけは例外**(6章)。`like` 色・700・**フル桁**で表示する
- 投稿カードの数値は演出中にカウントアップする。リプライカードの数値は静止でよい

### リプライ行は列幅を固定する

**`justify-between` で並べてはいけない。** 各行の数値の桁数によって配置が変わり、
リプライを縦に並べたときに**アイコンの縦の列が揃わず、ガタガタに見える**。

| 列 | 幅 | 根拠(最大桁) |
|---|---|---|
| 💬 リプライ | 48px | 返信数は最大2桁 |
| 🔁 ひろめる | 56px | 最大3桁 |
| ♡ エール | 68px | 最大4桁(`3,200`) |
| 📊 表示回数 | 残り全部 | `15.5万` など5文字 |
| ⬆ 共有 | 固定(28px) | 数値なし |

数値が無い行(インプレゾンビなど)でも**列幅は変わらない**。そのための固定幅である。

### アクション行の横幅

**アクション行は、その要素が置かれているカードの幅いっぱいに広げる。**
`justify-between` で均等配置し、**最大幅の上限を付けない。**

| 場所 | 広がる範囲 |
|---|---|
| 投稿カード | カードの内側の幅いっぱい(左右 `card-padding-x` を除いた全幅) |
| リプライカード | アバターの右側にある本文カラムの幅いっぱい |

> 上限幅を付けると、PC(600pxカラム)で**アイコン群が左に寄り、右半分が空く**。
> 本家はカード幅いっぱいに広げているため、上限を付けた時点で別物に見える。
> スマホ(375px)では見分けが付かないが、PCで並べると一目で違いが出る箇所。

### 時刻表記

リプライには `· 今` を付ける。投稿直後のタイムラインなので、本家でも全件が「今」になる。
経過時間を偽装する必要はない。

## 4-3. 入力画面(idle / composing)の仕様(2026-08-20 実物スクショで確認)

本家の投稿作成画面に寄せる。**上詰め・アバター横並び・投稿ボタンは上部右**が骨格。

```
┌─────────────────────────────┐
│ ヘッダー(Yロゴ + 履歴)         │ 53px
├─────────────────────────────┤
│                  [ ポストする ] │ ← 投稿バー。右にピルボタン
├─────────────────────────────┤
│ ◯  今日やったことを書いてみよう   │ ← アバター40px + 入力欄が横並び
│                             │
│         (広い余白)            │
│                             │
├─────────────────────────────┤
│ 🌐 全員が褒めてくれます      (◯) │ ← 左に表示テキスト / 右に円形カウンタ
└─────────────────────────────┘
```

| 要素 | 仕様 |
|---|---|
| **投稿ボタン** | 画面上部右のピル。ラベルは「**ポストする**」。`bg-accent` / `text-on-accent` / 700 |
| 投稿バーの下線 | **引かない。**ヘッダーの下線と2本並んで見え、間延びする(本家も引いていない) |
| 非活性時 | 本家と同じく**薄い青地に白文字**にする(`opacity` で全体を薄くしない) |
| **アバター** | 投稿カードと同じ「あなた」の40pxアイコン。入力欄の左に置く |
| **入力欄** | 上詰め。`text-compose`(20px)。プレースホルダは「今日やったことを書いてみよう」 |
| **返信範囲の行** | 🌐 + 「**全員が褒めてくれます**」。`accent` 色・`text-meta`。**表示専用でタップできない** |
| **文字数** | 右下に**円形のプログレスリング**。SVGの `stroke-dasharray` で実装。0文字のときは出さない |
| **入力欄の高さ** | 下部バーまでの余白いっぱいに広げる。**行数を固定しない**（長文で内部スクロールになり、空白をタップしてもフォーカスが当たらなくなる） |

### 本家から意図的に外すもの

| 外すもの | 理由 |
|---|---|
| 画像・カメラ・GIF・投票などのメディアアイコン列 | **このアプリに画像投稿の概念がなく、今後も入れない。**押しても何も起きないアイコンを6個並べることになる |
| 「キャンセル」ボタン | 本家の投稿画面はモーダルだが、本アプリでは入力画面が起点。**戻る先が存在しない** |

> **「全員が返信できます」を「全員が褒めてくれます」に変えた理由**
> 本家の要素をそのまま置いても本アプリでは意味を持たない(返信範囲の設定が無い)。
> 疑似SNS「H」の世界観に翻訳することで、本物らしさを保ちながら
> **投稿前に「これから褒められる」という期待値を上げる**役割を持たせられる。
> **押せるボタンにはしない。**表示専用テキストとして置く。

### 文字数カウンタの仕様

| 残り文字数 | 表示 |
|---|---|
| 21文字以上 | リングのみ。数字は出さない。色は `accent` |
| 20文字以下 | リング + 残り数字。色は黄系 |
| 0文字以下 | リング + 残り数字(マイナス)。色は `like`(赤ピンク)、投稿ボタンを非活性化 |

上限は本家と同じ280文字。

## 4-4. 待機画面(タイトル)

起動時に最初に出る全画面。**アプリ名と、何が起きるのかを1画面で伝える。**

```
┌─────────────────────────────┐
│                             │
│             H               │ ← 72px
│                             │
│          ほめられ             │ ← 28px / 700
│   やったことを書くだけで、        │ ← 15px / secondary
│   Hのみんなが一斉に褒めてくれます。  │
│                             │
│        タップして始める          │ ← 13px / 700 / accent
│                             │
└─────────────────────────────┘
```

| 項目 | 決定 |
|---|---|
| 入り方 | **画面のどこをタップしても**入力画面へ。ボタン領域を全画面にする |
| 出す条件 | 起動時に毎回。ただし**復帰(30分以内)のときは出さない**(結果画面へ直行する) |
| 「もう一度」 | 待機画面には戻らない。**入力画面に戻る**。連投したい人にタイトル画面は邪魔 |
| ヘッダー | 待機画面では**隠す**。ロゴが主役の画面なので二重に出さない |
| モーション | ロゴ → 文言 → 「タップして始める」の順に120ms差でフェードイン。**CSSで完結させる**(静止画面にGSAPを持ち込まない) |

> **入力画面の1行説明(旧 07章2節)は廃止し、この画面に統合した。**
> 同じ内容を2箇所で言う必要がない。

## 6. エール数の扱い(★唯一の意図的逸脱)

> **2026-08-20 改訂。** 旧版はここで「エール / ひろめる / リプライ」の3カウンタを
> 独立した巨大なメトリクス行として定義していたが、**本家に存在しない要素**であり、
> その下のアクション行から数字が消えてアイコンだけが並ぶ結果を招いていた。
> **メトリクス行は廃止。数値はアクション行に集約する**(4-2章)。
> 逸脱は以下の1点だけに縮小する。

### 逸脱するのはエール数の「表記」だけ

| 要素 | size | weight | color | 備考 |
|---|---|---|---|---|
| **エール数** | 13px | **700** | **`like`** | **常に3桁区切りのフル表示**(`22,147`) |
| その他のカウント | 13px | 400 | `text-secondary` | 万表記(`1,111` / `42.8万`) |
| 時刻行・表示回数 | 15px / 20px | 400 | `text-secondary` | |
| 表示回数の数値部分 | 15px / 20px | **700** | `text-primary` | 本家と同じ |

**なぜエール数だけフル桁なのか。**
「1.2万」表記ではカウントアップ中に数字がほとんど動かず、**このアプリの主役である
カウントアップ演出が一番地味になる**。また `9,999 → 1.0万` と表記が切り替わると
桁数が急に減り「数字が戻った」ように見える。ここだけは本家より優先する。

**なぜ `like` 色なのか。** 10章「エール数のピンクが画面内で唯一の強い色」を保つため。
本家はエールしたときだけピンクになるが、本アプリではエール数を常時ピンクにする。

### カウントアップの主役性をどう担保するか

巨大な数字が無くなる分、クライマックスは以下で作る。

| 手段 | 役割 |
|---|---|
| エール数の**桁の動き** | フル桁表示なので4〜5桁が絶えず回り続ける |
| **ハートバースト**(Phase C) | 画面全体を使う。演出の視覚的な主役 |
| **表示回数**(時刻行・15px/700) | エールよりわずかに先行して伸びる。桁が大きいので動きが目立つ |
| **トレンドバッジ**(Phase D 終盤) | 締めの一撃 |

- 全数値に `font-variant-numeric: tabular-nums` 必須(カウントアップ中に横幅が揺れるのを防ぐ)

## 7. モーション

| 対象 | duration | easing |
|---|---|---|
| 投稿カードの出現 | 600ms | `power2.out` |
| リプライカードの出現 | 400ms | `back.out(1.4)` |
| エール数のカウントアップ | フェーズ依存 | `power3.out` |
| ハートの飛翔 | 1200ms | `power1.out` |
| ボタンのホバー | 150ms | `ease-out` |

- リプライは `opacity: 0, y: 12px` から入る。左右からのスライドインは使わない(本家の挙動と乖離するため)
- `prefers-reduced-motion: reduce` の場合、カウントアップは最終値を即時表示し、リプライは順次フェードインのみにする

### 7-2. 操作感(マイクロインタラクション)

**「もっちゃりしている」と感じる原因はアニメーションの不足ではなく、モバイルブラウザの
既定挙動を殺していないこと**であることが多い。以下は `globals.css` に一括で書く。

| 対策 | 内容 | 効果 |
|---|---|---|
| **`touch-action: manipulation`** | ボタンに指定 | ダブルタップズーム判定の**待ち時間(約300ms)が消える**。反応の速さに直結する最重要項目 |
| **`-webkit-tap-highlight-color: transparent`** | ボタン・入力欄に指定 | タップ時にグレーの矩形が一瞬かぶるのを消す。**これが残っていると何をしても安っぽく見える** |
| **押下スケール** | `:active` で `scale(0.96)` / 100ms `ease-out` | 押した感触が出る。非活性のボタンには**かけない**(押せると誤解させるため) |
| **`user-select: none`** | ボタンに指定 | 長押しでラベルが選択されるのを防ぐ |
| **`caret-color: accent`** | 入力欄 | カーソルがブルーになる。本家と同じ |
| 文字数リングの補間 | `stroke-dashoffset` を150msで補間 | 1文字ごとにカクつかず滑らかに伸びる |
| 投稿時の触覚 | `navigator.vibrate(10)` | 押した瞬間に短く1回。Androidのみ有効 |

- `prefers-reduced-motion: reduce` のときは押下スケールを無効にする
- 押下スケールは `button:not(:disabled):active` で一括指定する。
  **各コンポーネントに個別のクラスを撒かない**(付け忘れが必ず出るため)

## 10. スクショ映え要件との整合

ライトテーマ確定に伴い、[02_X型演出_実装仕様.md](02_X型演出_実装仕様.md) の 9章「ダークテーマ前提」を撤回する。

白背景でスクショ映えを成立させるための条件:

- **エール数のピンク `#F91880` が画面内で唯一の強い色になる**ようにする。他の要素で彩度の高い色を使わない
- ハート演出のパーティクルもピンク単色。虹色などにしない
- `settled` 状態で画面下部に薄い区切り線とアプリ名を置き、「1枚の画像として完結している」印象を作る
- 白背景は SNS 上のライトモード表示と地続きになり、**「本当に投稿されたスクショ」に見えやすい** という利点がある
