# デザイントークン v1.0

- **アプリ名**: ほめられ
- **アプリ内の疑似SNS名**: **Y**(一文字ロゴ)
- **ベーステーマ**: ライト(白背景)
- **アクセント**: ブルー `#1D9BF0`

---

## 0. 方針

X のライトテーマのビジュアル言語を **そのまま踏襲する**。
配色・余白・フォントサイズ・角丸・アイコンサイズはすべて本家の数値を採用し、
独自化するのは **ロゴ・サービス名・アクション名** のみとする。

「見た瞬間にあのUIだと分かる」ことが体験の前提条件であり、
ここでオリジナリティを出すと疑似SNS演出そのものが成立しなくなるため。

### 唯一の意図的な逸脱

本家のカウント表記は `1.5万` のように丸められるが、本アプリでは
**エール数だけ常に3桁区切りのフル表示にし、`like` 色で出す**(6章参照)。
カウントアップ演出が体験の主役であり、丸め表記では数字が動かないため。
**サイズ・配置・情報の並びを含め、それ以外はすべて本家準拠とする。**

## 2. タイポグラフィ

### 2-1. フォントファミリー

X の本文フォント Chirp は **専用フォントで利用不可**。
本家も日本語部分はシステムフォントにフォールバックしているため、
以下のスタックで実質同じ見た目になる。

```css
--font-sans:
  -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto,
  "Helvetica Neue", "Hiragino Sans", "Hiragino Kaku Gothic ProN",
  "Noto Sans JP", Meiryo, sans-serif;
```

- **Webフォントは読み込まない。** システムフォントを使うことで表示が速く、かつ端末ごとにネイティブな見た目になる
- Google Fonts の Noto Sans JP を読み込む案もあるが、初期表示のちらつきとファイルサイズを避けるため採用しない

### 2-2. タイプスケール

| 用途 | size / line-height | weight | color |
|---|---|---|---|
| ポスト本文(投稿カード) | 17px / 24px | 400 | `text-primary` |
| リプライ本文 | 15px / 20px | 400 | `text-primary` |
| 表示名 | 15px / 20px | **700** | `text-primary` |
| ハンドル名・時刻 | 15px / 20px | 400 | `text-secondary` |
| メトリクスの数値(通常) | 13px / 16px | 400 | `text-secondary` |
| メトリクスのラベル | 13px / 16px | 400 | `text-secondary` |
| ボタンラベル | 15px / 20px | 700 | `text-on-accent` |
| 入力欄プレースホルダ | 20px / 24px | 400 | `text-secondary` |

- 入力欄だけ 20px と大きいのは本家準拠。「これから書く」ことを促す効果がある
- 数字を表示する要素にはすべて `font-variant-numeric: tabular-nums` を指定する

## 4. アバター・アイコン

| 要素 | サイズ | 角丸 |
|---|---|---|
| 投稿者アバター(投稿カード) | 40 × 40px | `border-radius: 9999px` |
| リプライのアバター | 40 × 40px | `border-radius: 9999px` |
| アクションアイコン | 18 × 18px | — |
| アイコンのホバー領域 | 34 × 34px | 円形 |

## 4-2. 本家準拠の細部(2026-08-20 実物スクショで確認)

実物と並べたときに「似ていない」と感じる原因は、配色ではなく**情報の密度と並び方**にある。
以下は実物の構造をそのまま踏襲する。

### 表示名とハンドルの並び

| 場所 | 並び |
|---|---|
| **投稿カード** | 表示名とハンドルを**縦2段**にする(`表示名` / 改行 / `@handle`) |
| **リプライカード** | 表示名・ハンドル・時刻を**横1行**に並べる(`表示名 @handle · 今`) |

投稿カードだけ2段なのが本家の仕様。ここを1行にすると情報が詰まって見え、主役感が出ない。

### アクション行には数値を併記する

**数値の置き場はアクション行だけ。** 独立したメトリクス行は置かない(6章)。

| 場所 | アイコンと数値 |
|---|---|
| 投稿カード | 💬 リプライ / 🔁 ひろめる / ♡ エール / 🔖 保存 / ⬆ 共有 の**5個**。共有以外に数値を出す |
| リプライカード | 💬 リプライ / 🔁 ひろめる / ♡ エール / 📊 表示回数 / 🔖 保存 / ⬆ 共有 の**6個**。前4つに数値を出す |

- **0 のときは数字を出さずアイコンのみ**にする。本家と同じ挙動
- 数値は `text-meta`(13px)・`text-secondary`・`tabular-nums`
- **エール数だけは例外**(6章)。`like` 色・700・**フル桁**で表示する
- 投稿カードの数値は演出中にカウントアップする。リプライカードの数値は静止でよい

### アクション行の横幅

**アクション行は、その要素が置かれているカードの幅いっぱいに広げる。**
`justify-between` で均等配置し、**最大幅の上限を付けない。**

| 場所 | 広がる範囲 |
|---|---|
| 投稿カード | カードの内側の幅いっぱい(左右 `card-padding-x` を除いた全幅) |
| リプライカード | アバターの右側にある本文カラムの幅いっぱい |

> 上限幅を付けると、PC(600pxカラム)で**アイコン群が左に寄り、右半分が空く**。
> 本家はカード幅いっぱいに広げているため、上限を付けた時点で別物に見える。
> スマホ(375px)では見分けが付かないが、PCで並べると一目で違いが出る箇所。

### 時刻表記

リプライには `· 今` を付ける。投稿直後のタイムラインなので、本家でも全件が「今」になる。
経過時間を偽装する必要はない。

## 6. エール数の扱い(★唯一の意図的逸脱)

> **2026-08-20 改訂。** 旧版はここで「エール / ひろめる / リプライ」の3カウンタを
> 独立した巨大なメトリクス行として定義していたが、**本家に存在しない要素**であり、
> その下のアクション行から数字が消えてアイコンだけが並ぶ結果を招いていた。
> **メトリクス行は廃止。数値はアクション行に集約する**(4-2章)。
> 逸脱は以下の1点だけに縮小する。

### 逸脱するのはエール数の「表記」だけ

| 要素 | size | weight | color | 備考 |
|---|---|---|---|---|
| **エール数** | 13px | **700** | **`like`** | **常に3桁区切りのフル表示**(`22,147`) |
| その他のカウント | 13px | 400 | `text-secondary` | 万表記(`1,111` / `42.8万`) |
| 時刻行・表示回数 | 15px / 20px | 400 | `text-secondary` | |
| 表示回数の数値部分 | 15px / 20px | **700** | `text-primary` | 本家と同じ |

**なぜエール数だけフル桁なのか。**
「1.2万」表記ではカウントアップ中に数字がほとんど動かず、**このアプリの主役である
カウントアップ演出が一番地味になる**。また `9,999 → 1.0万` と表記が切り替わると
桁数が急に減り「数字が戻った」ように見える。ここだけは本家より優先する。

**なぜ `like` 色なのか。** 10章「エール数のピンクが画面内で唯一の強い色」を保つため。
本家はエールしたときだけピンクになるが、本アプリではエール数を常時ピンクにする。

### カウントアップの主役性をどう担保するか

巨大な数字が無くなる分、クライマックスは以下で作る。

| 手段 | 役割 |
|---|---|
| エール数の**桁の動き** | フル桁表示なので4〜5桁が絶えず回り続ける |
| **ハートバースト**(Phase C) | 画面全体を使う。演出の視覚的な主役 |
| **表示回数**(時刻行・15px/700) | エールよりわずかに先行して伸びる。桁が大きいので動きが目立つ |
| **トレンドバッジ**(Phase D 終盤) | 締めの一撃 |

- 全数値に `font-variant-numeric: tabular-nums` 必須(カウントアップ中に横幅が揺れるのを防ぐ)

### 配置

```
┌────────────────────────────────────────┐
│ あなた                                   │
│ @anonymous                             │
│ 今日やったこと                              │
│                                        │
│ 午後10:23 · 2026年8月19日 · 42.8万 件の表示  │  ← 15px / 数値部分のみ700
│ ──────────────────────────────────     │
│  💬 847  🔁 2,104  ♡ 12,438  🔖 1,705  ⬆ │  ← 13px / エールのみ like色・700
└────────────────────────────────────────┘
```

### フォーマット規則(`lib/format.ts`)

| 値域 | 表記 | 例 |
|---|---|---|
| < 10,000 | 3桁区切り | `8,432` |
| 10,000 – 999,999 | 万・小数第1位 | `1.2万` / `42.8万` |
| ≥ 1,000,000 | 万・整数 | `124万` |

**エール数だけは例外で、常に3桁区切りのフル表示にする。**

## 7. モーション

| 対象 | duration | easing |
|---|---|---|
| 投稿カードの出現 | 600ms | `power2.out` |
| リプライカードの出現 | 400ms | `back.out(1.4)` |
| エール数のカウントアップ | フェーズ依存 | `power3.out` |
| ハートの飛翔 | 1200ms | `power1.out` |
| ボタンのホバー | 150ms | `ease-out` |

- リプライは `opacity: 0, y: 12px` から入る。左右からのスライドインは使わない(本家の挙動と乖離するため)
- `prefers-reduced-motion: reduce` の場合、カウントアップは最終値を即時表示し、リプライは順次フェードインのみにする

## 9. ロゴ「Y」の仕様

| 項目 | 内容 |
|---|---|
| 形 | 大文字の `Y` 一文字 |
| サイズ | ヘッダー内 28 × 28px |
| 色 | `text-primary`(`#0F1419`) |
| 書体 | 太めのサンセリフ。SVGでパス化して埋め込む(フォント依存を排除) |
| 配置 | ヘッダー中央、またはヘッダー左端 |

- 本家のロゴマークは一切使用しない
- ファビコン・OGP画像も `Y` を流用する
- アプリ名「ほめられ」は、`settled` 状態の画面下部に小さく併記する(スクショ拡散時の出典表示)

## 10. スクショ映え要件との整合

ライトテーマ確定に伴い、[02_X型演出_実装仕様.md](02_X型演出_実装仕様.md) の 9章「ダークテーマ前提」を撤回する。

白背景でスクショ映えを成立させるための条件:

- **エール数のピンク `#F91880` が画面内で唯一の強い色になる**ようにする。他の要素で彩度の高い色を使わない
- ハート演出のパーティクルもピンク単色。虹色などにしない
- `settled` 状態で画面下部に薄い区切り線とアプリ名を置き、「1枚の画像として完結している」印象を作る
- 白背景は SNS 上のライトモード表示と地続きになり、**「本当に投稿されたスクショ」に見えやすい** という利点がある
