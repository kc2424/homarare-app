# 褒めセリフ集 v1.1

通常6人格 × 10パターン + インプレゾンビ8パターン = **全68パターン**。
`src/lib/scenario/personas.ts` および `templates.ts` にそのまま反映できる形で記載する。

---

## 0. 執筆ルール(遵守必須)

セリフを追加・修正する際は必ず以下を守ること。

| ルール | 理由 |
|---|---|
| **否定・比較・アドバイスを入れない** | 「褒める」以外の要素が1つでも混ざると、安全な承認体験が壊れる |
| **「でも」「もっと」「次は」を使わない** | 条件付きの承認になり、自己評価が厳しい人ほど刺さらなくなる |
| **`{{deed}}` 埋め込みは全体の3割まで** | 入力が「ゴミを捨てた」等の短文だと日本語が破綻するため |
| **人格ごとの口調を最後まで崩さない** | 誰が言っているかが曖昧になると褒め言葉の重みが消える |
| **1文〜2文で完結させる** | リプライカードは2行程度が読みやすく、スクショにも収まる |

現在の `{{deed}}` 使用率: **7 / 60 = 約12%**(ルール内)

### リプライ自体につくエール数のレンジ

各リプライカードにも小さくエール数を表示する。人格によってレンジを変えることで、
「この人の言葉はみんなに刺さっている」という空気が生まれる。

| 人格 | likeCount レンジ |
|---|---|
| `kouhai` | 12 – 80 |
| `shinyu` | 30 – 150 |
| `senpai` | 200 – 900 |
| `mom` | 400 – 1,800 |
| `pro` | 800 – 3,200 |
| `stranger` | 150 – 700 |
| `zombie` | **2 – 40** |

> `mom` と `pro` を高めに設定しているのは、この2人格が「一番刺さるセリフ」を担っているため。
> 数字が大きいことで、読者自身も「これは名リプだ」と感じやすくなる。
>
> 逆に `zombie` は極端に低く設定する。誰にも相手にされていない数字であることが、
> インプレゾンビらしさとおかしみを生む。**ここを高くすると笑いが消えるので注意。**

## 2. セリフ全文

### 2-1. kouhai(素直な後輩・みなみ)

短く、素直に驚く。長文にすると後輩らしさが消えるので必ず1文で切る。

1. えっ、それめちゃくちゃすごくないですか…？
2. 普通にできないですよそれ。尊敬します
3. 自分だったら絶対後回しにしてました…
4. 「{{deed}}」ってサラッと言ってますけど、相当ですよ
5. 今日イチ気合い入ってるじゃないですか
6. わ、ほんとにやったんですね。すごい
7. 見習います。ほんとに
8. さらっとやってるのが一番かっこいいです
9. それ、自分もいつかできるようになりたいです
10. 「{{deed}}」← ここだけ切り取っても偉業です

### 2-2. shinyu(テンション高い親友・りょう)

勢いが命。文法の正しさより語感を優先する。絵文字は1〜2個まで。

1. いやそれめっちゃえらいって🎉
2. は？天才？？
3. よくやった!!!今日はもう休んでいいよ
4. 「{{deed}}」って書いてあるだけで拍手なんだが👏
5. でたー!!やると思ってた!
6. これ普通に自慢していいやつ✨
7. お前のそういうとこ、まじで好きだわ
8. 一番乗りで褒めとくわ。えらい!!
9. 今日の主役これでしょ🏆
10. ちょっと待って、それすごすぎない?

### 2-3. senpai(面倒見のいい先輩・タカハシ)

**「何が偉いのか」を具体的に言語化する**のがこの人格の役割。
漠然と褒めるだけの他人格との差別化点。

1. そこに気づけるのが一番えらいんだよ
2. 続けてるのが本当にすごい。結果は後からついてくる
3. 地味だけど、そういうのが一番効いてくるんだよな
4. ちゃんと手を動かしたのが偉い。頭の中で終わらせる人が大半だから
5. 「{{deed}}」、去年の自分にはできなかったことだろ
6. 誰にも見られてなくてもやったのが価値だよ
7. その調子。ちゃんと見てるからな
8. 完璧じゃなくていい。やったことが全部だよ
9. 自分のペースでいい。今日進んだのは事実だ
10. これ、後で効いてくるやつだから覚えとけ

### 2-4. mom(おかん的存在・かあちゃん)

**無条件の肯定**を担う人格。成果ではなく存在を褒める。
「ちゃんとごはん食べた?」など、褒めと気遣いをセットにするのがコツ。

1. よくがんばったねえ。ちゃんとごはん食べた?
2. えらいえらい。でも無理だけはしないでよ
3. 母さんは知ってるよ、あんたががんばってるの
4. すごいじゃない。今日はもう寝なさい
5. 「{{deed}}」、立派立派。ほんとに
6. あんたはやるときはやる子だからねえ
7. がんばりすぎて倒れないようにね。でも今日はよくやった
8. 誰がなんと言おうと母さんは褒めるよ
9. お疲れさま。あったかいもの食べなさい
10. そういうところ、昔から変わらないねえ。えらい

### 2-5. pro(その道のプロ・藤堂 慧)✔

**客観的な権威づけ**を担う人格。感情ではなく評価として褒める。
認証バッジが付くので、他人格より一段「重い」言葉に感じられる。

1. これは実際に難易度が高い。淡々とやれる人は少ないです
2. 継続の価値は後から効いてきます。今日の一歩は確実に資産です
3. 手をつけた時点で上位です。多くの人はここまで来ません
4. 「{{deed}}」— これを言語化して記録している時点で価値があります
5. 客観的に見て、十分な成果です
6. 小さく見えるかもしれませんが、方向は完全に正しいです
7. 自己評価と実績が乖離しているタイプですね。もっと誇っていい
8. この積み重ねが、半年後に明確な差になります
9. 再現性のある動き方をしています。それが一番大事です
10. 一日の成果としては申し分ありません

### 2-6. stranger(通りすがりの他人・な)

**「知らない人が褒めてくれる」**という体験の要。
本アプリのコンセプト(承認欲求を安全に満たす)に最も直接的に効く人格。

1. 通りすがりですが、わかります。それ本当にえらいです
2. 知らない人ですけど、拍手させてください👏
3. 今日これ見て、自分もがんばろうと思えました
4. 流れてきただけなのに、めちゃくちゃ励まされました
5. 「{{deed}}」、自分はできてないです。すごい
6. こういう投稿が伸びてほしい
7. 見ず知らずですが、ちゃんと偉いと思います
8. なんか泣きそう。おつかれさまです
9. 保存しました。自分もやります
10. 誰も言ってくれないなら自分が言います。えらい!

### 2-7. zombie(インプレゾンビ)🌐

**このアプリで最もスクショされるパーツになる想定の人格。**

アラビア語で長文のリプライが2〜3件連投される。一見すると典型的なインプレゾンビだが、
「翻訳を表示」を押すと **全力で褒めていたことが判明する** というオチ。

#### 設計意図と注意点

| 項目 | 方針 |
|---|---|
| アラビア語は**本物を使う** | それっぽい記号の羅列にすると、単に外国語をバカにする表現になる。実際に褒めている文章を書くことで、オチが「実はいい奴だった」という温かい方向に着地する |
| 訳文も**本気の褒め言葉**にする | 翻訳して初めて成立するネタなので、訳文の質がそのままウケの質になる |
| 出現は Phase C 後半〜D | 反応が出揃った終盤に湧くのがインプレゾンビの実態に近い |
| **重複出現を許可する唯一の人格** | 2〜3体が別アカウントとして連続で湧く。1体だとネタとして弱い |
| エール数は極端に低く(2–40) | 誰にも相手にされていない数字であることがおかしみになる |

## 3. `{{deed}}` 展開時の処理仕様

埋め込み型テンプレートを使う際、以下の処理を `buildScenario` 内で行う。

```ts
function expandTemplate(template: string, deed: string): string {
  // 長すぎる入力は末尾を省略（リプライカードが崩れるため）
  const trimmed = deed.length > 24 ? `${deed.slice(0, 24)}…` : deed;
  return template.replaceAll("{{deed}}", trimmed);
}
```

- **24文字を超えたら省略記号で切る。** リプライは2行以内に収めたいため
- 入力が空文字の場合、埋め込み型テンプレートは抽選対象から除外する
- 改行を含む入力は、埋め込み時にスペースへ置換する

## 4. 抽選ロジックの仕様

```
1. 表示リプライ数 n を 8〜12 でランダム決定
2. うち zombie を 2〜3 件分、確定で確保する（n から差し引く）
3. 残り枠を通常6人格から重複なしで選ぶ
   - 残り枠 > 6 の場合は、6人格を一巡させたあと 2 周目に入る
   - 2周目では 1 周目と異なるテンプレートを引くこと（同一人格の重複発言を許容する代わりに、
     セリフの重複は絶対に避ける）
4. 各人格のテンプレート配列から重複なしで抽選
5. zombie は ZOMBIE_IDENTITIES から重複なしでアカウントを割り当て、
   ZOMBIE_TEMPLATES から重複なしでセリフを割り当てる
6. 出現フェーズ制約を適用して appearAt を決定
   - kouhai / shinyu は Phase B (1.2–3.5s) に最低1件配置
   - pro は Phase C 後半 (6.0s 以降) に配置
   - stranger は Phase D (8.0s 以降) に最低1件配置
   - zombie は 8.5s 以降。かつ 2〜3件を 0.4s 以内の短い間隔で連投させる
7. appearAt 昇順にソートして ReactionItem[] を返す
```

> **ゾンビは「連投」であることが重要**
> 通常のリプライは 0.3〜0.6s 間隔で降ってくるが、ゾンビだけは 0.4s 以内に固めて出す。
> 一斉に湧いてくる挙動そのものがネタの一部なので、他の人格と同じ間隔で出してはいけない。

> **なぜフェーズ制約が必要か**
> ランダムに並べると、いきなり `pro` の重い評価から始まってしまうことがある。
> 「素朴な反応 → 熱狂 → 権威づけ → 見知らぬ人の共感」という順序があるからこそ、
> 反応が広がっていく感覚が生まれる。ここは必ず制御する。
